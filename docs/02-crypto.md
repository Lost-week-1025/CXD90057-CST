# 02 · 加密

## 算法（4th-gen AesCbcCrypter）

```
载荷 L = frames × 1024 + 272
[0, 512)   AES-128-ECB, key = key_aes
[512, L)   AES-256-CBC, key = 机型密钥, IV = 载荷尾 -0x110
```

第 0 块被切成两半：前半 ECB，后半及其后全部 CBC；CBC 的 IV 只为第一块后半服务。

## 密钥

| 用途 | 值 / 来源 |
|---|---|
| ECB（前 512 B） | `key_aes` = `E3B0C44298FC1C149AFBF4C8996FB924`（**跨代复用**） |
| CXD90045 CBC | `key_cxd90045` |
| **A6700 / A7R V CBC** | **`key_cxd90057_k8`** = `434589432D319010F1132727353286CE4D7EDE8B9C4F7217A0E0226E0F0EDC69` |

CXD90057 有两个密钥集：`k0` 与 `k8`。**A6700 实测用 k8**（k0 → 6/6 块全错）。

## ⚠️ IV 对齐陷阱

`fwtool` 的 `AesCbcCrypter.decrypt()`：

```python
file.seek(-0x110, 2)      # 相对"传入的 file 对象"末尾
self._iv = file.read(0x10)
```

| IV 起点 | 结果 |
|---|---|
| `N-272`（若对**整个 DAT**取） | `ok=5 bad=1` |
| **`N-284`（对 **FDAT 载荷**取）** | **`ok=6 bad=0` ✅** |

原因：CBC 链中 **IV 只影响 block0 的后 512 字节**，block1 起用上一块密文做链。
所以 IV 取错表现为「**只有首块校验失败、其余全过**」——极具迷惑性。

→ `decryptFdat()` 必须传入 **FDAT 载荷切片**，不能传整个 `.DAT`。

## trailer 272 字节

```
载荷[-272:-256]   16 B   AES-CBC IV
载荷[-256:  0]   256 B   RSA-2048 签名
```

> 重打包时 trailer 前 16 B 的 IV **不要**跟着 AES 雪崩一起重算——它本来就是明文。

## 密钥的正确用途

这些密钥来自公开上游项目，用途是**格式研究与兼容性验证**（确认自己手里的镜像是否是
原厂件、能否反向构造测试样本）。它们不赋予任何绕过签名的能力——签名是 RSA，与 AES 无关。
