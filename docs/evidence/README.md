## 这张图证明了什么

索尼的更新流程分两个阶段，信任边界不同：

```
阶段一「识别」  appFw.so 读 FdatHeader[32:34] 决定是否提示      ← 本图发生在这里
阶段二「执行」  nflasha1 的 updater 验 RSA-2048 后写 flash      ← 未触发
```

**阶段一不验 RSA。** 本项目重打包的固件只改了 `FdatHeader[32]`（`versionMinor` `0x00 → 0x01`）
并重算了 header CRC32 / L3 帧校验 / DEND CRC32，**RSA 签名必然失效**（无私钥），
但相机仍然把它当作合法的 v2.01 接受并提示更新。

**所以：能从 SD 卡触发「发现新版本」≠ 能刷进去。** 这两件事常被混为一谈。



## 为什么不提供固件

固件本体、改动版产物、重打包脚本都不在本仓库：

- 固件体量 1 GB，且属索尼版权物
- 重打包脚本暂不公开 —— 完整的 fastboot 写入 + 重打包闭环尚未跑完，
  fastboot 工具链还在路上（详见 `docs/06-rescue-and-ei.md`）

本目录只保留**现象证据与数值**，任何人有官方固件都能按 `docs/03-integrity.md`
的方法自行复算校验。
